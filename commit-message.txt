음성 인식을 GPU 로: 윈도우 CUDA DLL 경로 문제 해결

RTX 4070 이 있는데도 whisper 가 CPU 로 돌고 있었다.
`cublas64_12.dll is not found` 때문이었는데, 그래픽카드 문제가 아니라
**DLL 을 찾는 방법**의 문제였다.

원인
  파이썬 3.8 부터 윈도우에서 확장 모듈이 의존하는 DLL 을 PATH 에서
  찾지 않는다. 그래서 pip 가 아래에 잘 깔아놓아도 아무도 못 찾는다.

      .venv\Lib\site-packages\nvidia\cublas\bin\cublas64_12.dll

  즉 `pip install nvidia-cublas-cu12` 만으로는 안 고쳐진다.
  os.add_dll_directory() 로 그 폴더를 직접 등록해야 하고,
  faster_whisper 를 import 하기 **전에** 해야 한다.

새 파일
  cuda_dlls.py   site-packages 의 nvidia/*/bin 을 찾아 등록한다.
                 stt.py 가 모델을 올리기 직전에 부른다.
                 등록 핸들을 모듈 수준에 붙잡아 둔다 - 지역 변수에만
                 담으면 함수를 나가는 순간 등록이 풀린다.
                 어떤 경우에도 예외를 내지 않는다. 여기서 터지면
                 GPU 를 못 쓰는 정도가 아니라 음성 인식이 죽는다.

  gpu_check.py   6단계로 짚는다: 가상환경 -> 그래픽카드 -> 패키지 버전
                 -> DLL -> CUDA 장치 -> 실제 추론.
                 마지막까지 통과해야 진짜다. WhisperModel(device="cuda")
                 는 라이브러리가 없어도 객체 생성은 성공하고, 계산할 때가
                 되어서야 죽기 때문이다.
                 막히면 오류 문구에 맞는 처방을 내놓는다.

실측 (이 PC)
  RTX 4070 12GB, 드라이버 591.86
  ctranslate2 4.8.2 + nvidia-cudnn-cu12 (9.x)  -> 동작
  cuDNN 은 버전을 맞춰야 한다. ctranslate2 4.5.0 부터 cuDNN 9,
  그 아래는 cuDNN 8. 엇갈리면 cudnn_ops64_9.dll not found 가 계속 난다.

설정 변경
  STT_MODEL  small -> medium   (GPU 에서 CPU 의 small 보다 빠르다)
  STT_DEVICE auto 유지          - 다른 PC 로 옮겼을 때 오류로 멈추는 대신
                                CPU 로 내려가게 하기 위함
  STT_BEAM   1 유지             - 한 번에 하나씩 바꾼다. medium 효과를
                                먼저 확인한 뒤에 건드린다

huggingface 심볼릭 링크 경고를 껐다. 기능에는 영향이 없고 콘솔만
어지럽힌다.

실기 확인
  음성 명령으로 전진/후진/좌우 회전 모두 동작.
  앉거나 엎드렸다 일어난 뒤의 회전도 정상 - 오늘 오전에 common 에 넣은
  StopMove 가 음성 경로에도 그대로 적용됐다.
  남은 미검증은 04_guide_demo.py 하나.
