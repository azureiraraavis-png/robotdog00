# robotdog00 — Go2 PRO 한국어 안내 로봇

Unitree Go2 PRO가 **한국어로 말하면서 방문객을 안내하도록** 만드는 프로젝트입니다.

앱에 딸린 음성 비서(벤벤)는 한국어를 알아듣지 못하고 손댈 수도 없습니다.
그래서 앱을 거치지 않고 **PC에서 로봇에 직접 붙어**, 한국어 음성을 만들어
로봇 스피커로 내보내고, 한국어 명령으로 움직이게 합니다.

> A Korean-language voice guide built on the Unitree Go2 PRO.
> The stock BenBen assistant is a closed loop to Unitree's servers with no way to add
> Korean, so this controls the robot directly over the same WebRTC path the app uses —
> local Whisper for Korean speech recognition, edge-tts for synthesis, played through
> the robot's own speaker. Documentation is in Korean; the findings section below may
> be useful to anyone working with a Go2, especially on a non-English Windows locale.

## 현재 상태

| | 상태 |
|---|---|
| PC → 로봇 제어 연결 (WebRTC, AES 인증) | ✅ 실기 확인 |
| 한국어 음성 → 로봇 스피커 재생 | ✅ 실기 확인 |
| 연속 재생 (여러 문장을 이어서) | ✅ 실기 확인 |
| 안전하게 눕히기 / 들어 올리기 / 넘어짐 복구 | ✅ 실기 확인 |
| 자세 감시 (기울기 읽기) | ✅ 실기 확인 |
| 보행 (`02_move_test.py`) | ⬜ 미검증 |
| 한국어 음성 인식 (`05_voice_control.py`) | ⬜ 미검증 |
| 안내 통합 데모 (`04_guide_demo.py`) | ⬜ 미검증 |

**기체**: Unitree Go2 **PRO** (오디오 재생은 PRO/EDU 전용), 펌웨어 MCF 모드

## 왜 앱으로는 안 되는가

앱 안의 **벤벤(BenBen)** 음성 대화는 `앱 → 유니트리 서버 → 앱` 으로 닫힌 구조입니다.
공개된 API도 없고, 한국어를 추가할 창구도 없습니다. 벤벤을 고치려는 시도는 계속 막힙니다.

대신 **앱이 쓰는 것과 똑같은 WebRTC 통신 경로**로 로봇에 직접 붙습니다.
펌웨어 개조도, 탈옥도 없습니다. 그러면 이런 것들이 가능해집니다.

| 하고 싶은 것 | 방법 |
|---|---|
| 한국어 알아듣기 | PC/폰에서 처리 (Whisper, 브라우저 음성인식, 안드로이드 STT) |
| 한국어로 대답하기 | TTS로 mp3 생성 → **로봇 스피커로 재생** |
| 걷기·제스처 | sport 명령 직접 전송 |

**로봇 스피커 재생은 Go2 PRO/EDU에서만 지원됩니다.** 우리 기체는 PRO이므로 해당됩니다.

## 준비물

- **Windows PC** (또는 노트북) — **Python 3.10 ~ 3.12** (3.13/3.14는 안 됩니다, 아래 참고)
- **ffmpeg** — 음성 변환에 필요합니다
- 로봇과 PC가 **같은 네트워크**에 있을 것
- **유니트리 계정** — AES 키를 받으려면 이 기체가 바인딩된 계정이어야 합니다

### 설치

```powershell
# 1) ffmpeg (없으면)
winget install Gyan.FFmpeg

# 2) 가상환경
cd D:\workspace_raraavis\robotdog00
python -m venv .venv

# 3) 패키지 — 활성화 없이 venv의 python을 직접 호출합니다
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

실행할 때도 같은 방식으로 부릅니다.

```powershell
.\.venv\Scripts\python.exe 01_connect_test.py
```

> PowerShell 실행 정책 때문입니다. 위처럼 `python.exe` 를 직접 부르면 정책과
> 무관하게 동작하므로, 굳이 활성화할 필요가 없습니다.
>
> 활성화를 쓰고 싶다면 (관리자 권한 불필요):
> ```powershell
> Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
> ```
> 조직 그룹 정책으로 잠겨 있으면 이것도 거부됩니다. 그때는 위의 직접 호출 방식을 쓰세요.

### ⚠ Python 버전 — `pyaudio` 빌드 실패의 원인

`fatal error C1083: 'portaudio.h': No such file or directory` 로 설치가 실패한다면
**파이썬 버전이 너무 최신**입니다. `pyaudio` 는 3.13/3.14용 미리 빌드된 휠이 아직 없어서
pip이 직접 컴파일을 시도하다 실패합니다.

**Python 3.12 로 가상환경을 다시 만드세요.**

```powershell

py install 3.12             # 없으면 설치 (또는 winget install Python.Python.3.12)

Remove-Item -Recurse -Force .venv
py -V:3.12 -m venv .venv    # 구버전 런처는 py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

`.\.venv\Scripts\python.exe --version` 이 3.12 로 나오면 정상입니다.

> `pyaudio` 는 **PC 쪽 마이크/스피커**용이라 01~04 스크립트는 직접 쓰지 않습니다.
> 다만 라이브러리의 필수 의존성이라 설치는 되어야 합니다.
> 나중에 PC로 음성 입력을 받는 단계에서 실제로 쓰이게 됩니다.

## 네트워크 구성

가장 안정적인 조합입니다.

```
   폰 (핫스팟 제공, 셀룰러로 인터넷)
     ├── 로봇 Go2 PRO      ← 같은 LAN
     └── PC (이 코드 실행)  ← 같은 LAN + 인터넷
```

로봇을 **AP 모드가 아니라 Wi-Fi(STA) 모드**로 붙여야 합니다.
앱에서 `Device → 네트워크 설정 → Wi-Fi 모드` 로 전환하세요.
앱의 로봇 목록에서 `Off-line` 이 `On-line` 으로 바뀌면 성공입니다.

로봇의 IP는 앱의 기기 정보에서 확인할 수 있습니다.

## AES 키 받기

**펌웨어 1.1.15 이상은 기기별 AES-128 키가 없으면 연결이 거부됩니다.**
이 기체는 업데이트를 여러 번 했으므로 해당될 가능성이 높습니다.

**한국어 Windows 에서는 딸려오는 `unitree-fetch-aes-key` 명령이 동작하지 않습니다.**
대신 이 폴더의 스크립트를 쓰세요.

```powershell
.\.venv\Scripts\python.exe get_aes_key.py
```

비밀번호는 프롬프트로 물어봅니다. **명령줄에 적지 마세요** — 특수문자를 PowerShell이
해석해버리고, 히스토리 파일에 평문으로 남습니다.

성공하면 바인딩된 로봇 목록과 함께, 그대로 붙여넣을 수 있는 환경변수 설정 줄을 출력합니다.

> **왜 별도 스크립트인가**
> 라이브러리가 HTTP 헤더에 시스템 시간대 이름을 그대로 넣는데, 한국어 Windows에서는
> 그 값이 `"대한민국 표준시"` 로 나옵니다. HTTP 헤더는 latin-1만 허용하므로
> `UnicodeEncodeError: 'latin-1' codec can't encode characters in position 0-3` 로
> 죽습니다. `get_aes_key.py` 는 그 헤더만 안전한 값으로 바꿔치기해 우회합니다.
> 라이브러리 파일 자체는 건드리지 않습니다.

- **이 기체가 그 계정에 바인딩되어 있어야 합니다.** 공용 장비라면 관리자에게
  계정 접근이나 키 값을 요청하세요.
- 계정이 중국 가입이면 `config.py` 의 `UNITREE_REGION` 을 `"cn"` 으로 바꾸세요.

받은 32자리 키를 환경변수에 넣습니다.

```powershell
$env:GO2_IP = "192.168.x.x"
$env:GO2_AES_KEY = "여기에32자리16진수"
```

매번 입력하기 번거로우면 `config.py` 의 기본값을 직접 고쳐도 됩니다.
단, 그 경우 키가 파일에 남으니 외부 공유에 주의하세요.

## ⚠ 전원을 켤 때 발버둥치는 문제

로봇이 켜자마자 뒤집히거나 네 발을 빠르게 휘젓는 일이 있습니다.
원인은 두 가지가 겹친 것입니다.

1. **시작 자세가 잘못됨** — 다리가 벌어진 채로 켜면 기립 동작이 몸을 밀어냅니다
2. **자동 복구(Auto Recovery)** — 로봇이 "넘어졌다"고 판단해 스스로 일어나려 합니다.
   바닥이 미끄럽거나 자세가 이상하면 성공하지 못하고 **계속 재시도**하는데,
   그게 발버둥치는 것처럼 보입니다

### 소프트웨어로 막을 수 없는 구간

**전원을 켜는 그 순간은 코드로 손댈 수 없습니다.** 우리 프로그램이 로봇에
붙기 전이기 때문입니다. 이 구간은 절차로만 막습니다.

- [ ] **배가 바닥에 닿고 다리를 완전히 접은 상태**로 눕혀 놓고 켜기
- [ ] 평평하고 미끄럽지 않은 바닥 (매끈한 타일 위에서는 특히 잘 미끄러집니다)
- [ ] **켜는 사람이 리모컨을 손에 들고 있기** — `L2 + B` 가 가장 빠른 정지
- [ ] 발끝 비닐 제거 (접지가 없으면 기립에 실패하고 넘어집니다)

### 헷갈리기 쉬운 두 가지 — 자동 복구 ≠ 힘 빼기

별개의 장치입니다. 둘 다 필요합니다.

| | 무엇을 막나 | 어떻게 |
|---|---|---|
| **자동 복구 끄기** | 넘어졌다고 판단해 스스로 일어나려는 **발버둥** | 연결할 때 자동 |
| **댐핑(Damp)** | 관절에 힘이 들어가 자세를 **버티는 것** | 명시적으로 실행 |

`01_connect_test.py` 는 자동 복구만 끕니다. 로봇을 움직이지 않는 스크립트라
힘은 빼지 않아요. 그래서 실행 후에도 로봇은 **서서 균형을 잡고 있고**,
들어 올리면 다리가 자세를 유지하려 저항합니다. 그건 발버둥이 아니라 버티기입니다.

출력의 `몸높이` 로 구분할 수 있습니다. **0.3 안팎이면 서 있는 것**이고,
**0.1 아래면 엎드려 힘이 빠진 것**입니다.

### ⚠ 들어 올릴 때가 특히 위험합니다

전원이 켜진 로봇의 **등 손잡이를 잡고 들어 올리면 발이 땅에서 떨어집니다.**
로봇은 그것을 **넘어진 것**으로 해석하고 스스로 일어나려 발버둥칩니다.
다리가 빠르게 꺾이며 움직이므로 **손이 그 사이에 있으면 다칩니다.**

옮기기 전에 반드시:

```powershell
.\run carry.py
```

자동 복구를 끄고 힘을 뺀 뒤, **연결을 열어둔 채 대기**합니다. 옮기는 동안
설정이 유지되도록 그 창은 닫지 마세요. 다 옮기면 Enter.

리모컨이 있으면 `L2 + B` (힘 빼기) 후 들어 올려도 됩니다.

### ⚠ 자동 복구 설정은 재부팅하면 초기화됩니다

실측으로 확인했습니다. 껐더라도 **전원을 껐다 켜면 다시 켜져 있습니다.**

그래서 이 프로젝트는 **연결할 때마다** 자동으로 끕니다 (`common.connect()` 안에서).
어떤 스크립트를 실행하든 붙는 순간 꺼지므로, 따로 신경 쓰지 않아도 됩니다.

다만 **전원을 켜고 아직 아무것도 연결하지 않은 구간**은 여전히 무방비입니다.
그 사이에 들어 올리거나 자세를 흐트러뜨리면 발버둥칩니다.
켠 직후에는 아무것이든 한 번 연결해서 설정을 꺼두는 것이 안전합니다.

```powershell
.\run 01_connect_test.py     # 30초, 로봇을 움직이지 않으면서 자동 복구를 꺼둡니다
```

### 소프트웨어로 되는 것

연결한 뒤부터는 아래가 일합니다.

```powershell
.\run recover.py          # 힘 빼고 → 자동 복구 끄고 → 필요하면 일으키기
.\run recover.py off      # 자동 복구만 끄기
.\run recover.py on       # 다시 켜기
```

- **자동 복구 끄기** — 넘어져도 발버둥치지 않고 가만히 있습니다.
  사람이 상황을 보고 판단할 수 있게 됩니다. **시연 환경에서는 꺼두는 쪽을 권합니다.**
- **자세 감시(Watchdog)** — `02`, `04`, `05` 는 실행 중 로봇의 기울기를 지켜보다가
  60도를 넘으면 **즉시 힘을 뺍니다**. 쓰러진 채로 관절에 힘이 들어가 있으면
  모터가 계속 버티려 하면서 발열과 마모가 생기기 때문입니다.
  이 스크립트들은 시작할 때 자동 복구도 함께 끕니다.

### 이미 발버둥치고 있다면

1. **리모컨 `L2 + B`** — 가장 빠릅니다. 손에 있다면 이것부터
2. 리모컨이 없으면 `.\run recover.py` — 붙는 데 2~3초 걸립니다
3. **그동안 손을 대지 마세요.** 다리가 빠르게 움직입니다
4. 완전히 뒤집혔으면 스스로 못 일어납니다. 힘을 뺀 뒤 **손으로 배가 바닥을
   향하도록 돌려 눕히고** 나서 일으키세요

## 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| `RobotBusyError` | **폰 앱이 아직 붙어 있습니다.** 앱을 완전히 종료하고 10~20초 기다리세요. 로봇은 한 번에 하나의 클라이언트만 받습니다. |
| `AesKeyRequiredError` | 펌웨어가 키를 요구합니다. 위의 'AES 키 받기'를 따르세요. |
| `AesKeyRejectedError` | 키가 이 기체의 것이 아닙니다. SN과 region을 확인하세요. |
| `LocalSignalingPortError` | IP가 틀렸거나, 로봇이 꺼져 있거나, 다른 네트워크에 있습니다. |
| 소리가 안 남 | 볼륨(0~10)을 확인하세요. 스크립트가 7~8로 올립니다. 그래도 안 되면 앱에서 로봇 스피커가 정상인지 먼저 확인하세요. |
| mp3 변환 실패 | **ffmpeg 이 없습니다.** `winget install Gyan.FFmpeg` |
| 곡예 동작만 안 먹음 | 펌웨어 1.1.7+ 는 MCF 모드일 수 있습니다. `SPORT_CMD` 대신 `SPORT_CMD_MCF` 를 써야 합니다. `01` 이 현재 모드를 알려줍니다. |

## ⚠ 운영상 주의

**펌웨어 업데이트가 이 연결을 깨뜨릴 수 있습니다.**
비공식 경로이기 때문에, 유니트리가 프로토콜을 바꾸면 라이브러리가 따라잡을 때까지
동작하지 않습니다.

- 개발이 본격화되면 **펌웨어 버전을 고정**하세요.
- **시연 직전에는 절대 업데이트하지 마세요.**
- 업데이트가 필요하면 시연 후, 여유 있을 때 하고 곧바로 재검증하세요.

## 앞으로의 방향

이 폴더가 검증하는 것은 **"PC가 로봇을 제어하고 한국어로 말하게 할 수 있다"** 까지입니다.
그다음은 이렇게 이어집니다.

```
방문객 한국어 발화
  → 마이크 (지향성 USB 마이크 권장 — 전시장은 시끄럽습니다)
  → 한국어 STT   (Whisper / 브라우저 Web Speech API / 안드로이드 STT)
  → 의도 분류 또는 LLM
  → ├ 한국어 TTS → 로봇 스피커   ← 이 폴더에서 이미 검증됨
    └ sport 명령 → 로봇 동작      ← 이 폴더에서 이미 검증됨
```

**APK는 마지막에 만드세요.** 순서를 이렇게 잡으면 위험이 훨씬 적습니다.

1. **지금 여기** — PC 파이썬으로 제어와 음성 검증
2. **웹앱** — PC에서 페이지를 띄우고 폰 크롬으로 접속.
   브라우저의 Web Speech API가 한국어 STT/TTS를 공짜로 해줍니다. APK 불필요.
   (마이크 권한 때문에 HTTPS가 필요합니다 — 로컬 터널로 해결)
3. **APK** — 웹앱이 검증된 뒤 WebView로 감싸거나 네이티브로 재작성.
   이 시점엔 무엇을 만들지가 이미 확정되어 있습니다.

전시장 네트워크가 못 미더우면 안드로이드 **오프라인 한국어 인식**을 내려받아 두면
고정 어휘로는 인터넷 없이도 동작합니다.

## 삽질 기록 — 이 프로젝트에서 알아낸 것들

문서 어디에도 없어서 직접 부딪혀 알아낸 것들입니다.
같은 자리에서 헤매지 않도록 남겨둡니다.

### 오디오

**1. mp3 가 끝나면 송신 루프가 죽습니다**
`MediaPlayer` 로 만든 트랙을 `pc.addTrack()` 하면 첫 파일은 잘 나갑니다. 그런데 파일이
끝나는 순간 트랙이 `MediaStreamError` 를 던지고, 그걸 받은 aiortc 송신 루프가 **종료**됩니다.
그 뒤로는 `replaceTrack()` 으로 새 음원을 꽂아도 읽어가는 쪽이 없어 영원히 무음입니다.
→ **끝나지 않는 트랙**을 만들어야 합니다. 재생할 게 없으면 무음 프레임을 계속 내보내
   송신 루프를 살려두고, 내부에서 음원만 갈아끼웁니다. (`common.ContinuousAudioTrack`)

**2. 무음 프레임의 박자를 `sleep(0.02)` 로 세면 안 됩니다**
매번 20ms 보다 조금씩 더 걸려서 **실측 1.8% 씩 뒤처집니다** (1분에 약 1초).
그만큼 수신 버퍼가 말라가다 소리가 끊기고 결국 멈춥니다.
→ 시작 시각 기준으로 각 프레임이 나가야 할 시각을 계산해 기다립니다. (실측 0.1%)

**3. 오디오 채널을 명시적으로 켜야 합니다**
`switchAudioChannel(True)` 를 보내지 않으면 트랙을 보내도 스피커에서 소리가 안 납니다.
라이브러리 예제(`play_mp3.py`)조차 이 호출을 빠뜨리고 있습니다.

**4. `replaceTrack` 은 동기 함수입니다**
`await` 를 붙이면 `TypeError` 가 납니다. (aiortc 1.15 기준)

**5. 스피커 볼륨 눈금이 비선형입니다**
1~2 는 거의 안 들리고 7 이상은 꽤 큽니다. 실용 구간이 3~6 으로 좁습니다.
미세 조정은 TTS 쪽 음량(`edge-tts` 의 volume)으로 하는 편이 낫습니다.

### 연결

**6. 연결을 닫지 않고 종료하면 유령 세션이 남습니다**
로봇은 한 번에 하나의 WebRTC 클라이언트만 받습니다. `Ctrl+C` 로 그냥 빠져나오면
로봇 쪽에 세션이 남아 다음 실행이 이상하게 동작합니다. `finally` 로 반드시 닫으세요.

**7. `input()` 이 연결을 끊습니다**
asyncio 루프 안에서 그냥 `input()` 을 부르면 이벤트 루프가 통째로 멈춥니다.
그동안 심장박동 신호가 나가지 못해 **로봇이 연결을 끊습니다.**
사람이 화면을 읽고 답하는 십여 초면 충분히 끊깁니다.
→ `await asyncio.to_thread(input, ...)`

**8. 명령에 시간 제한이 없으면 조용히 멈춥니다**
연결이 끊긴 뒤 명령을 보내면 오지 않을 응답을 영원히 기다립니다. 화면에 아무 설명도
없이요. `asyncio.wait_for` 로 감싸고, 시간이 지나면 무슨 일인지 알려주세요.

**9. 멀티캐스트가 막혀도 포트 스캔으로 찾을 수 있습니다**
`discover_ip_sn()` 이 실패해도 로봇은 살아 있을 수 있습니다.
같은 대역을 훑어 신호 포트(9991, 8081)가 열린 기기를 찾으면 됩니다. (`find_robot.py`)

### 안전

**10. 자동 복구는 재부팅하면 다시 켜집니다**
`SetAutoRecovery`(MCF 2054) 로 끌 수 있지만 **전원을 껐다 켜면 초기화됩니다.**
→ 특정 스크립트가 아니라 **연결할 때마다** 꺼야 합니다.

**11. 들어 올리면 로봇은 "넘어졌다"고 판단합니다**
등 손잡이를 잡고 들면 발이 땅에서 떨어지고, 로봇은 일어나려 발버둥칩니다.
다리가 빠르게 꺾이므로 손이 그 사이에 있으면 다칩니다.
→ 들기 전에 반드시 자동 복구를 끄고 힘을 빼세요. (`carry.py`)

**12. `Damp` 전에 반드시 `StandDown` 을 거쳐야 합니다**
서 있는 상태에서 곧바로 힘을 빼면 그대로 무너지며 '쿵' 떨어집니다.
제어된 동작으로 눕힌 다음에 힘을 빼세요. (`common.settle()`)

**13. 자동 복구 끄기 ≠ 힘 빼기**
별개입니다. 전자는 발버둥을 막고, 후자는 버티기를 막습니다. 들어 올리려면 둘 다 필요합니다.
`몸높이` 로 구분할 수 있습니다 — 0.3 안팎이면 서 있는 것, 0.1 아래면 힘이 빠진 것.

### 환경

**14. 한국어 Windows 에서 `unitree-fetch-aes-key` 가 죽습니다**
라이브러리가 HTTP 헤더에 시스템 시간대 이름을 그대로 넣는데, 한국어 환경에서는
그 값이 `"대한민국 표준시"` 입니다. HTTP 헤더는 latin-1 만 허용하므로
`UnicodeEncodeError: 'latin-1' codec can't encode characters in position 0-3` 로 죽습니다.
영어 환경에서는 `"Korea Standard Time"` 이라 재현되지 않습니다.
→ 해당 헤더만 바꿔치기해 우회합니다. (`get_aes_key.py`)

**15. `pyaudio` 는 Python 3.13/3.14 용 휠이 없습니다**
`portaudio.h: No such file` 로 빌드가 실패합니다. Python 3.12 를 쓰세요.

**16. 배치 파일(.cmd)에 한글을 넣으면 안 됩니다**
cmd 는 배치 파일을 바이트 오프셋 기준으로 읽습니다. 멀티바이트 문자로 오프셋이 어긋나면
파일 중간부터 다시 읽는 **무한 루프**에 빠집니다. 순수 ASCII 로 작성하세요.

**17. 펌웨어 1.1.7+ 는 MCF 모드일 수 있습니다**
기본 동작(`StandUp`/`Move`/`Hello`/`Damp` 등)은 `SPORT_CMD` 와 번호가 같지만
곡예·자율 계열은 다릅니다 (`BackFlip` 1044 → 2043, `FreeWalk` 1045 → 2045).
`MOTION_SWITCHER` api_id 1001 로 현재 모드를 먼저 확인하세요.
